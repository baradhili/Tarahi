# corpus/

Test fixtures for Tarahi. Two tiers, kept strictly separate so the
clean-room status of the project is never at risk.

## Layout

    corpus/
      synthetic/   # tracked in git — generated by a committed builder
      imported/    # tracked in git - generated by a person - must be leagal to publish, no raw client drawings!
      README.md    # this manifest

## synthetic/  (tracked, always runs in CI)

Files here are generated by committed Rust code that builds .vsdx
packages from scratch through dc-core. They contain no Microsoft
content, no reporter IP, no real-user data. They run on every CI
build and never skip.

Rules:

- Never hand-edit a file in synthetic/. If a test needs a different
  fixture, change the builder, regenerate, commit the result.
- Filename describes the feature under test, not the issue number
  (e.g. multi_page_text.vsdx, not issue263.vsdx).
- A row in the manifest below is required.

## imported/  

Files here are .vsdx/.vssx/.vstx packages supplied by issue reporters
to reproduce real-world bugs. They are committed.
Treat any file in this directory as untrusted third-party material.

Rules:

- Filename should match the issue (kreuzung.vsdx for #303) so the
  link is obvious.
- A row in the manifest below is required, including the source
  issue and the reporter attribution.

## Adding a new fixture

### If the bug can be reproduced from scratch (preferred)

1. Write a builder function in dc-core (or extend an existing one)
   that constructs the minimal .vsdx exhibiting the bug.
2. Add a generator target that writes the output to
   corpus/synthetic/<name>.vsdx.
3. Commit the builder and the generated .vsdx.
4. Add a row to the manifest above (tier = synthetic).
5. Write the test against corpus::synthetic("<name>.vsdx").

### If you need a real-Visio file from the reporter

1. Save the file as corpus/imported/<name>.vsdx. 
2. Add a row to the manifest above, with the source
   issue and reporter attribution.
3. Write the test against corpus::local("<name>.vsdx")
4. Confirm the test PASSES locally with the file present.

## Resolver

All test code resolves corpus paths through the helper in
crates/dc-ui/tests/common/ (and a sibling in crates/dc/tests/).
Never write `../../../` escapes — they break the moment a test file
moves (the module splits will move several), and they hide which
tier (synthetic vs imported) the file came from.
